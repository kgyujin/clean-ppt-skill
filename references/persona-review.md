# 네 관점 검토와 수정

이 절차는 시각적 문제를 찾는 검토입니다. 실제 사용자 조사나 모두가 만족한다는 보증이 아닙니다. 도구 권한이 있거나 사용자가 요청한 경우 별도 에이전트와 병행할 수 있습니다. Claude 등 다른 도구를 실제로 실행하지 않았다면 공동 검토로 기록하지 않습니다.

| 관점 | 확인할 질문 | 수정 예시 |
| --- | --- | --- |
| 발표자 | 어디부터 설명할지 보이는가? | 강조 지점을 하나로 줄이고 설명 순서를 노트에 기록 |
| 청중 | 작은 화면에서 중요한 조건까지 읽히는가? | 본문 확대, 캡처 잘라내기, 긴 문단 분할 |
| 디자이너 | 구조가 내용과 맞고 정렬이 일정한가? | 열 너비·기준선 통일, 장식 축소, 반복 카드 재배치 |
| 근거 검토자 | 계획·실측·예시가 구분되는가? | 숫자 옆 상태와 단위 표시, 근거 없는 인과 표현 제거 |

## 공통 품질 기준

- 제목과 소제목, 본문을 구분하되 같은 역할의 글자 크기를 장마다 임의로 바꾸지 않습니다. 1280×720에서 본문 24~30px, 제목 40~44px를 출발점으로 삼습니다. 큰 표지 제목과 숫자는 별도 역할입니다.
- 푸터처럼 읽기 우선순위가 낮은 요소만 작게 씁니다. 중요한 조건을 푸터로 숨기지 않습니다.
- 텍스트가 잘리거나 의도치 않게 겹치면 수정 전에는 전달하지 않습니다. 색만으로 통과·실패나 전후를 구분하지 않습니다.
- 흐름선은 실제 순서와 맞아야 합니다. 예쁘게 보이기 위한 순환 화살표, 원문에 없는 재시도나 승인 단계를 추가하지 않습니다.
- 시각자료와 본문이 같은 사실을 보여야 합니다. 비례 막대는 실제 값과 맞고, 계획 수치를 성과처럼 꾸미지 않습니다.
- 발표자 노트가 있어도 슬라이드 자체에 핵심 조건과 출처 맥락을 남깁니다.

## 검수 방법

1. 전체 축소판으로 반복 구조와 밀도를 봅니다.
2. 각 장을 100%와 노트북 화면 크기로 봅니다. 축소판만으로 작은 글씨가 읽힌다고 판단하지 않습니다.
3. `scripts/check_scene_layout.py`로 캔버스, 글자 넘침, 겹침과 대비를 검사합니다. `--font-regular`와 `--font-bold`를 주어 실제 폰트 폭으로 계산합니다.
4. 대비·겹침 경고는 맥락을 보고 판단합니다. 의도한 겹침은 이유를 기록하며, 통과를 위해 검사 임계값을 완화하지 않습니다.
5. 문제를 수정하고 최신 파일을 다시 렌더합니다. 세 관점 이상의 실제 지적과 반영 내용을 기록합니다.

자동 검사는 지원하는 장면 요소의 범위만 확인합니다. 사진 위 글자와 실제 PowerPoint 줄바꿈은 별도 확인 대상입니다. 빈 공간 비율, 카드 수, 표 열 수를 획일적인 미적 점수로 쓰지 않습니다. 사진·화면 캡처까지 편집 가능한 텍스트로 바꾸라는 요구도 하지 않습니다.
