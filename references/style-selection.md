# 짧은 요청에서 디자인을 고르는 기준

사용자는 자료와 목적만 알려도 됩니다. 색, 글자 크기, 도형 위치를 질문 목록으로 돌려주지 않습니다. 발표 시간이나 형식이 자료에서 확인되지 않으면 합리적인 기본값을 짧게 밝힙니다. 사실 확인이 필요한 정보는 스타일 선택과 별도로 처리합니다.

## 시작 순서

1. 기존 발표 수정이면 기존 내용과 사용자가 좋아한 요소를 먼저 보존합니다.
2. 새 발표이면 청중, 목적, 자료의 주된 형태를 파악합니다. 주제만 있고 근거가 없으면 초안임을 구분하고 수치나 성과를 만들지 않습니다.
3. 아래에서 한 스타일을 골라 해당 미리보기와 JSON을 읽습니다. 같은 발표의 폰트, 제목 축, 강조 색은 유지합니다.
4. 비교·절차·수치·캡처 등 장의 역할에 따라 본문을 바꿉니다. 세 장 예제를 그대로 순환시키거나 모든 장을 세 카드로 채우지 않습니다.
5. 글씨를 줄이기 전에 문장을 다듬거나 배치를 바꿉니다. 그래도 넘치면 장을 나눕니다.

## 선택표

| 자료와 목적 | 우선 스타일 | 구성의 특징 |
| --- | --- | --- |
| 일반 기획, 기존과 개선 설명 | editorial | 비대칭 열, 큰 제목, 비교 열 |
| 교육, 팀 회고, 차분한 설명 | warm | 따뜻한 바탕, 두 역할 비교, 수직 일정 |
| 코드, 구조, 도구 실행 과정 | technical | 왼쪽 탐색 영역, 명확한 흐름 방향 |
| 검토 회의, 의사결정, 핵심 요약 | executive | 상단 요약, 행 중심 매트릭스, 결정 순서 |
| 제품 소개, 포트폴리오, 짧은 소개 | studio | 큰 타이포, 넓은 구분선, 번호 중심 편집 |

우선순위는 사용자 지정 스타일 > 기존 브랜드 > 발표 목적 > 기본 editorial입니다. 표의 키워드가 하나 보였다고 기계적으로 고르지 않습니다. 예를 들어 기술 제품의 투자 제안은 코드보다 의사결정 자료가 중심일 수 있습니다.

## 선택안이 필요한 경우

“다양하게”, “몇 가지 시안”, “분위기를 모르겠어”가 있으면 구조가 다른 세 스타일의 표지와 대표 본문을 먼저 렌더합니다. 같은 정보로 비교하고, 색만 다른 안을 여러 디자인으로 세지 않습니다. 사용자가 자동 완성을 요청했다면 가장 적합한 안을 선택해 전체 자료까지 마칩니다. 취향 선택이 필수라는 이유로 매번 작업을 멈추지 않습니다.

한 덱 안에서 서로 다른 스타일을 무작위로 섞지 않습니다. 강조 색, 글꼴, 제목 위치는 일정하게 두고 본문의 구조를 다양하게 만듭니다. 표지만 멋있고 나머지는 빈 페이지가 되지 않도록 본문 두 장 이상을 함께 확인합니다.

## 예제 사용

[스타일 목록](../assets/style-catalog.json)은 각 스타일의 이미지와 원본 위치를 제공합니다. [기본 레이아웃](../templates/README.md)은 비교·수치·조건 분기처럼 특정 역할을 보충할 때 사용합니다. 레이아웃을 옮길 때 선택한 스타일의 여백과 타이포에 다시 맞춥니다.

자료가 적다면 5분 발표도 3~5장으로 구성할 수 있습니다. 분량을 채우기 위해 가상의 기능이나 성과를 추가하지 않습니다. 예제의 출처 표시, 승인, 재시도 등 입력 자료에 없는 기능도 자동으로 복사하지 않습니다.

예제의 30개 문서, 3명, 2주는 가상의 시험 계획입니다. 사용자가 제공한 사실과 수치로 교체해야 합니다. 성과처럼 보이는 큰 숫자에는 단위와 상태를 가까이 표시합니다.
