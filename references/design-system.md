# V9에서 일반화한 디자인 기준

## 기본 토큰

| 용도 | 기본값 |
|---|---|
| 캔버스 | 1280×720px를 13⅓×7½인치에 대응시킨 16:9 |
| 바탕 | 흰색 FFFFFF |
| 본문 / 보조 글자 | 192A40 / 526174 |
| 강조 / 옅은 면 / 선 | 2459A6 / EEF3F9 / CDD6E1 |
| 서체 | Pretendard Regular와 Bold |
| 바깥 여백 | 좌우 56px, 내용 하단 648px 이내 |
| 제목 | x56, y79, 폭1168, 약44px = 33pt |
| 상단 정보 | y30, 13px = 9.75pt, 필요할 때만 |
| 부제 | y157, 21~24px = 15.75~18pt |
| 본문 시작 | 일반적으로 y211~226 |
| 본문 | 24~29px = 18~21.75pt |
| 코드 / 보조 설명 | 20~23px = 15~17.25pt, 읽을 양을 제한 |
| 주석 / 푸터 | 12~16px = 9~12pt, 발표 중 읽도록 요구하지 않음 |
| 선과 화살표 | 1~2px, 화살촉 끝과 도착 개체 사이 간격 일정 |

표의 px→pt 대응은 위의 물리적 슬라이드 크기를 전제로 한다. 다른 크기에서는 다시 계산한다. 수치는 출발점이다. 브랜드와 입력 자료가 다르면 바꾸되, 바꾼 체계를 전체 문서에서 유지한다. 폰트를 찾지 못하면 조용히 다른 글꼴로 출력하지 말고 사용 가능한 한국어 폰트를 선택해 전체에 반영하고 알린다. 기본 그라데이션, 검은 표지, 네온색, 과도한 그림자와 장식용 3D 이미지는 넣지 않는다. 사용자가 명시하면 그 요청을 우선한다.

## 배치별 원리

- 표지: 짧고 큰 제목, 발표 정보와 주제의 시각자료. 본문 전체를 미리 설명하지 않는다.
- 개선 전후: 행마다 같은 개선 지점을 비교한다. 원래 문제와 바뀐 동작을 같은 기준으로 쓴다.
- 대화 예시: 발화 순서와 바뀌거나 유지되는 정보가 보이게 한다. 원본 그대로의 캡처와 대화 요약 도식을 구분한다.
- 실행 결과: 글자가 실제로 읽히는 크기로 두 영역 정도를 크게 쓴다. 꾸미는 상자보다 근거의 면적을 먼저 확보한다.
- 과정: 위쪽에는 핵심 흐름, 아래에는 조건과 필요한 짧은 코드. 단순 직선이 아닌 분기와 복귀를 의미대로 표시한다.
- 정량 결과: 단위를 붙인 표나 차트를 사용한다. 큰 숫자를 설명·상자·차트에서 불필요하게 세 번 반복하지 않는다.
- 마무리: 배운 점이나 결정 사항을 분명하게 남긴다. 표지를 복제하거나 흔한 감사 문구로만 채우지 않는다.

## 품질을 판단할 질문

색을 모두 회색으로 바꿔도 읽는 순서가 남는가? 중요한 근거를 먼저 보게 되는가? 같은 속성은 같은 자리에 있는가? 전체 화면에서 잘 보이지만 개별 캡처는 흐리지 않은가? 강조 색과 굵기를 동시에 과하게 쓰지 않았는가?

## V9 비교·결과 영역

- 비교: 행 제목 x56, 기존 열 x244~662, 개선 열 x742~1224. 열 머리글 y216~268. 본문 핵심은 각 행 y+7에서 같은 기준선, 보조 설명은 y+49. 행 높이 102px. 기존 머리글은 회색, 개선 머리글은 파랑, 개선 본문은 아주 옅은 파랑.
- 수치 비교: 두 지표를 좌우로 나누고 각 지표의 기존→개선을 큰 숫자로 표시. 단위를 가까이 배치하고, 같은 지표의 막대 길이는 실제 값에 비례. 서로 다른 단위의 두 지표를 같은 축으로 비교하지 않음.
- 표에 같은 내용을 핵심 문구와 설명으로 두 번 쓰지 않음. 설명은 핵심에 없는 조건이나 맥락을 담음.
- 템플릿은 V9의 색·서체·위계를 바탕으로 다듬은 가상 예제이며 원본 페이지의 그대로인 복제는 아님.
- 일반 표는 세로 격자 없이 가로선만 사용. 정보량에 맞춘 열 폭과 제목·행 라벨·값의 위계를 유지.
